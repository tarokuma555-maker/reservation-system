# reservation-system

お掃除の家事代行・片付けコンサル向け、LINE公式アカウント連携の予約システム。

- **公開中のデモ: <https://reservation-system-olive.vercel.app>**
- [要件定義書](docs/requirements.md)

## 概要

| 項目 | 内容 |
|---|---|
| 顧客インターフェース | LINE公式アカウント（リッチメニュー + LIFF） |
| サービス提供形態 | 訪問（お掃除・片付けコンサル）とオンライン（片付けコンサル）の2形態 |
| 提供機能（顧客） | 予約・変更・キャンセル、定期利用の登録／変更／スキップ／解約、予約履歴、領収書の確認 |
| 提供機能（管理） | スケジュール管理、定期予約のイレギュラー対応、顧客・メニュー管理、インボイス発行、経費と証憑の管理、帳簿と決算書 |
| 外部連携 | LINE Messaging API / LIFF、Googleカレンダー（Meet URLの自動発行を含む）、Cloud Vision（レシートOCR） |
| 決済 | 現金・銀行振込。オンライン決済は将来対応 |
| 会計 | 売上の自動仕訳、経費と証憑（電子帳簿保存法対応）、計算書類4表と消費税集計。**申告書の作成と提出は対象外**（税理士の独占業務） |

## デモの動かし方

Node.js 20以上が必要です。**認証情報の設定なしでそのまま動きます。**

```bash
npm install     # 依存関係の取得（Prismaの準備まで自動で走ります）
npm run setup   # DBを作り、デモデータを投入する
npm run dev     # http://localhost:3000 が立ち上がります
```

うまくいかないときは `npm run db:reset` でデータを作り直せます。

| 入口 | 内容 |
|---|---|
| `/liff` | **お客様側**（LINEのトーク画面とリッチメニューを再現） |
| `/admin` | **管理画面** |

お客様側の画面上部の黒いバーで、**操作するお客様を切り替えられます**。
本番ではLIFFがLINEユーザーIDを取得しますが、デモでは切替で代用しています。

### 切り替えて試せる4名

| お客様 | 特徴 | 確認できること |
|---|---|---|
| 佐藤 美咲 | 世田谷区・2LDK・定期利用中 | 訪問予約、定期のスキップ、領収書 |
| 山田 健一 | 目黒区・3LDK以上・ペットあり | 間取りによる所要時間の補正（+60分） |
| 小林 あかり | **住所の登録なし（遠方）** | 訪問がエリア外で選べず、オンラインへ誘導される |
| 株式会社みらいオフィス | **法人・登録番号あり** | インボイスの宛名が法人名になる |

## 公開デモ（Vercel）

<https://reservation-system-olive.vercel.app>

`main` ブランチへのpushで自動的に再デプロイされます。環境変数の設定は不要で、DBの用意もデモデータの投入もビルドに含まれています。

サーバーレス向けに以下を自動で処理しています。

| 項目 | 対応 |
|---|---|
| SQLiteが読み取り専用の場所に置かれる | 起動時に `/tmp` へコピーして使う |
| ビルド時の日付で固定されてしまう | 起動後の最初のアクセスで、今日を基準にデータを作り直す |
| ヘッドレスChromiumが無い | PDF生成は印刷用ページへ退避し、ブラウザの印刷からPDFにできる |

状態の確認用に `/api/debug/db` を用意しています。DBファイルの所在・件数・データの投入日が返ります。

> デモのデータは各インスタンスの `/tmp` にあるため、しばらく放置すると初期状態に戻ります。触った内容を残したい段階になったら、PostgreSQLに切り替えます。

## ライブモードとモックモード

LINE・Googleカレンダー・OCRは、**認証情報の有無でモードが自動で切り替わります。**
コードの分岐は入口の1箇所だけで、その先の処理は両モードで共通です。

| 機能 | モックモード（既定） | ライブモード（環境変数を設定） |
|---|---|---|
| LINE通知 | 送信するJSONを組み立ててDBに保存。`/liff/talk` と `/admin/messages` で確認できる | 同じJSONをMessaging APIへ実送信 |
| LINE Webhook | 署名検証を省略し、管理画面から疑似イベントを流せる | `X-Line-Signature` を検証。イベントIDで冪等処理 |
| リッチメニュー | 登録処理をモックし、構成を画面で確認できる | Messaging APIに登録してユーザーへリンク |
| Googleカレンダー | Google側の状態を `CalendarEvent` テーブルで再現 | Calendar APIへ実際に書き出し・取り込み |
| Meet URL | 予約ごとに固有のURLを生成 | `conferenceData` でGoogle Meetを実発行 |
| レシートOCR | 同梱のサンプルレシート文面を使用 | Cloud Vision APIで写真から読み取り |
| PDF生成 | **常に実物**（ヘッドレスChromiumでA4のPDFを生成） | 同じ |

切り替えは `.env.example` をコピーして値を入れるだけです。

```bash
cp .env.example .env
```

必要なもの:

- **LINE**: LINE Developers でMessaging APIチャネルを作成 → チャネルアクセストークンとチャネルシークレット。Webhook URL に `<APP_BASE_URL>/api/line/webhook` を登録
- **Googleカレンダー**: Google Cloud で Calendar API を有効化 → OAuthクライアント → オーナーのアカウントで認可してリフレッシュトークンを取得
- **OCR**: Cloud Vision API のAPIキー

## デモで確認できること

**予約まわり**

1. **提供形態で分岐する予約フロー** — 訪問とオンラインで必要な情報も空き枠の出方も変わる
2. **移動時間バッファの4パターン** — 前後の予約の組み合わせで必要時間を計算。埋まっている枠は理由を表示
3. **定期予約のイレギュラー対応** — 「今回だけ休む」「今回だけ日時変更」をしてもルール変更で消えない

**LINE連携**（`/admin/messages` と `/liff/talk`）

4. 予約確定・変更・キャンセル・前日リマインド・オンライン直前・実施後のお礼・領収書送付をFlex Messageで送信。**実際に送るJSONをそのまま確認できる**
5. Webhookの疑似イベント送信（友だち追加・ブロック・メッセージ・ポストバック）と、**同じイベントIDの再送を無視する冪等処理**
6. リッチメニュー2種（未予約者向け／予約保有者向け）の構成と登録

**Googleカレンダー同期**（`/admin/calendar-sync`）

7. 予約の書き出し（訪問は住所を「場所」に、オンラインはMeet URLを発行）
8. **「Google側で消してみる」→「不整合を検知して復元する」** で、システム側を正として復元されることを確認できる
9. Googleに入れた私用予定の取り込み（ブロック枠になり、空き枠から外れる）。システムが作ったイベントは取り込まれない

**インボイス・会計**

10. 適格請求書の発行（法定6項目の検証、税率ごとに1回だけの端数処理）
11. **PDFの実生成**とLINEでの送付。生成したPDFは証憑として保存される
12. **レシートOCR** → 日付・金額・取引先・登録番号の抽出 → 勘定科目の推定 → 仕訳の作成
13. **証憑ボックス** — 取引年月日・金額・取引先での検索（電子帳簿保存法の検索要件）。保存期限内は削除が拒否され、その操作も履歴に残る
14. **帳簿と決算書** — 試算表・仕訳帳・減価償却・計算書類4表（B/S、P/L、株主資本等変動計算書、個別注記表）
15. **消費税集計** — 本則課税と簡易課税の試算比較、インボイスの有無による控除額の違い

### 設定値はすべて仮置き

料金・営業時間・移動バッファ・登録番号・決算月・対応エリアなどは仮の値です。
`/admin/settings` から変更でき、空き枠の計算や書類の表示にすぐ反映されます。

### デモと本番の違い

| 項目 | デモ | 本番 |
|---|---|---|
| データベース | SQLite（追加のインフラなしで動くため） | PostgreSQL |
| 外部連携 | 認証情報がなければモックモード | 環境変数を設定してライブモード |
| バッチ処理 | 管理画面のボタンで手動実行 | Vercel Cron で定時実行（リマインド送信・定期予約の生成・カレンダー差分同期） |
| 管理画面の認証 | なし | メール+パスワード + 2要素認証 |
| 証憑ストレージ | ローカルファイル | S3互換（バージョニングとオブジェクトロックを有効化） |
