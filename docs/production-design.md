# 本番化 設計書

デモを「実際に使えるシステム」にするための設計。
デモとの違いと、そのために何を作り替えるかをまとめる。

- 対象: 家事代行・片付けコンサル向け LINE予約システム
- 前提: 置き場所は Vercel + 本番用PostgreSQL、管理画面のログインは Googleアカウント
- 版: 1.0

---

## 0. この設計の要点

デモは「認証情報が無ければお試しモードで動く」という作りだった。
本番では逆に、**認証情報を入れる作業そのものを画面の機能にする**。

| | デモ | 本番 |
|---|---|---|
| 合いことばの置き場所 | 環境変数（開発者しか触れない） | **画面から入力**。暗号化してDBに保存 |
| つなぎ替え | 環境変数を書き換えて再デプロイ | **画面のボタンで即座に差し替え** |
| Googleカレンダー | リフレッシュトークンを手作業で取得 | **「つなぐ」ボタン → Googleの確認画面 → 完了** |
| 管理画面 | 誰でも開ける | Googleログイン必須。許可したメールアドレスのみ |
| データベース | SQLite（再起動で消える） | PostgreSQL（消えない） |

つなぎ替えを画面でできるようにするのは、ご要望どおり
**「いまはご自身の公式LINE、あとでお客さま側で作ったアカウントへ乗り換える」**
を、こちらの作業なしで行えるようにするため。

## 2. データベース: SQLite → PostgreSQL

### 変えるところ

| 項目 | 内容 |
|---|---|
| provider | `sqlite` → `postgresql` |
| スキーマ変更の方法 | `prisma db push` → `prisma migrate`（変更履歴が残り、巻き戻せる） |
| `src/lib/db.ts` | `/tmp` へコピーする仕掛けを削除。ふつうの接続プールに戻す |
| 接続 | サーバーレス向けにプール接続（`DATABASE_URL`）とマイグレーション用の直結（`DIRECT_URL`）を分ける |

金額は引き続き**整数の円**で持つ。小数を使うと1円ずれるため。

### 初期データ

デモと同じ内容を初期データとして投入する（ご要望どおり、入った状態から始める）。
本番で初めて動かすときだけ流し、以降は流さない。
実際のメニュー・料金が決まったら、管理画面から書き換えるか、こちらで差し替える。

## 3. 管理画面のログイン

お客様のお名前・ご住所・お電話番号をお預かりする以上、**誰でも開ける状態のままにはできない**。

| 項目 | 内容 |
|---|---|
| 方式 | Googleアカウントでログイン（Auth.js + Google OAuth） |
| 入れる人 | `Staff` テーブルにメールアドレスが登録されている人だけ |
| 最初の1人 | `ADMIN_EMAILS` に書いたアドレスは、初回ログイン時に自動で登録される |
| 守る範囲 | `/admin/**` と管理用の更新処理すべて。`/liff/**` は対象外（お客様が使うため） |
| ログインしていない場合 | ログイン画面へ飛ばす |
| スタッフを増やす | 管理画面からメールアドレスを追加する |

カレンダー連携でもGoogleアカウントを使うため、入口がひとつにまとまる。
ただし**ログイン用と、カレンダーを読み書きする許可は分けて求める**。
ログインのたびに「カレンダーを見てもいいですか」と聞かれるのは不親切なため。

## 4. 合いことば（認証情報）の扱い

### 保管方法

新しく `Connection` テーブルを作る。

| 列 | 内容 |
|---|---|
| provider | `line` / `google_calendar` / `google_vision` |
| credentials | 合いことば本体。**AES-256-GCMで暗号化して保存** |
| status | `connected` / `error` / `disconnected` |
| label | 「〇〇の公式アカウント」など、どれに繋がっているかの目印 |
| connectedAt / connectedBy | いつ・誰が繋いだか |
| lastCheckedAt / lastError | 最後に確認した日時と、失敗したときの理由 |

暗号鍵は環境変数 `ENCRYPTION_KEY` に置く。データベースが漏れても合いことばだけは読めない。

### 画面に出すときは伏せる

保存した合いことばは**画面に出さない**。末尾4文字だけ見せて、入っていることが分かるようにする。
差し替えるときは新しい値を貼り直す。

### つなぎ替え

「つなぎ替える」ボタンで、いつでも別のLINEアカウントに向け直せる。
その際、以下を自動で行う。

1. 新しい合いことばで疎通を確認する（失敗したら古い設定のまま残す）
2. LINEの下のメニューを、新しいアカウント側に登録し直す
3. 「つなぎ替えました」と履歴に残す

**既存の予約・顧客・帳簿はそのまま残る。** LINEユーザーIDだけがアカウントごとに変わるため、
乗り換え時は「お客様に、新しいアカウントを友だち追加していただく」案内が必要になる。
この案内文も画面から送れるようにする。

## 5. LINE連携

### 5.1 必要なもの

| もの | どこで手に入るか | 誰がやるか |
|---|---|---|
| チャネルアクセストークン | LINE Developers → Messaging API | **オーナー**（画面の手順に沿って） |
| チャネルシークレット | LINE Developers → チャネル基本設定 | **オーナー** |
| Webhook URL の登録 | LINE Developers に貼り付け | **オーナー**（画面からURLをコピーできる） |
| LIFF ID | LINE Developers → LIFF | **オーナー** |
| メニューの背景画像 | — | **こちらで自動生成**（下記） |

### 5.2 メニューの背景画像を自動で作る

リッチメニューには 2500×1686 の画像が要る。デザイナーに頼むのが普通だが、
**同梱のアイコンとお店の名前から、その場で画像を生成する**ようにする。
PDF生成に使っているヘッドレスブラウザで、HTMLを画像として書き出す。

これにより、オーナー側の準備が「合いことばを貼る」だけで済む。
後から自前の画像に差し替えることもできる。

### 5.3 お客様の見分け方（LIFF）

デモでは画面上部の切替で代用していた部分。本番では:

1. LIFF が LINE から IDトークンを受け取る
2. サーバーで LINE に照会して本物か確かめる（改ざん防止）
3. 中に入っている LINEユーザーID で顧客を特定する
4. 初めての方なら、その場で顧客を作る

**IDトークンの検証をサーバー側で必ず行う。** ブラウザから送られてきた
ユーザーIDをそのまま信じると、他人の予約を覗けてしまうため。

### 5.4 Webhook

| 項目 | 内容 |
|---|---|
| 署名の確認 | 必須。合いことばが入っているのに署名が合わなければ拒否する |
| 二重処理の防止 | イベントIDで判定（デモと同じ仕組みをそのまま使う） |
| 友だち追加 | LINEから表示名とアイコンを取得して顧客を作り、ごあいさつを送る |
| ブロック | 顧客に印をつけ、以降の送信対象から外す |
| 応答の速さ | 受け取ったらすぐ200を返し、重い処理は後ろに回す |

## 6. Googleカレンダー連携

### デモとの違い

デモではリフレッシュトークンを手作業で取得する必要があった。本番では画面で完結させる。

```
「カレンダーをつなぐ」を押す
      ↓
Googleの確認画面（ご自身のアカウントでログイン）
      ↓
「このアプリにカレンダーを見せてもいいですか」→ はい
      ↓
戻ってきたら完了。以降は自動で更新される
```

| 項目 | 内容 |
|---|---|
| 求める許可 | `calendar`（読み書き）のみ。メールや連絡先は求めない |
| リフレッシュトークン | `access_type=offline` で取得し、暗号化して保存 |
| 書き出し先 | つないだ後、カレンダーの一覧から選べるようにする |
| どちらが正か | **このシステムが正**。Google側で消されても復元する（デモと同じ） |
| 私用予定の取り込み | このシステムが作ったイベントは取り込まない（二重防止） |

### 取り消されたとき

オーナーがGoogle側で許可を取り消すと、更新が失敗する。
その場合は `status` を `error` にして、管理画面のホームに
「カレンダーとのつながりが切れています」と出し、つなぎ直しを促す。

## 7. 定時実行

Vercel Cron で動かす。受け口は `CRON_SECRET` で守り、外から叩かれないようにする。

**いまのプラン（Hobby）では、定時実行は「1日1回のものを2つまで」しか置けない。**
そのため毎日ぶんは1つにまとめ、`/api/cron/daily` として毎日18:00に動かす。

| まとめて動くもの | 何を |
|---|---|
| 前日のおしらせ | 明日のご予約に「明日おうかがいします」を送る |
| 定期の予定づくり | 定期のお客様の予定を3か月先まで用意する |
| カレンダーの修復 | Googleカレンダーとのずれを直し、失敗ぶんをやり直す |
| 疎通の確認 | LINEとGoogleのつながりが切れていないか確かめる |

1つ失敗しても残りは動かす。カレンダーの不調で前日のおしらせが止まると、
お客様にご迷惑がかかるため。

### まだ動かせないもの

**オンライン開始前のおしらせ**（15分前）だけは、1日1回では実現できない。
受け口 `/api/cron/online-soon` は用意してあるので、選択肢は2つ。

| やり方 | 費用 | 備考 |
|---|---|---|
| Vercel Proにする | 月20ドル | 15分おきの実行がそのまま使える |
| 無料の外部スケジューラを使う | 無料 | cron-job.org などから受け口を呼ぶ。合いことばを設定する必要がある |

急ぐ機能ではないので、実際に運用を始めてから決めればよい。

## 8. ファイルの保管

| 項目 | デモ | 本番 |
|---|---|---|
| 領収書PDF | サーバー上のファイル | Vercel Blob |
| 消えないようにする | — | 上書き・削除を禁止する設定にする |
| 保存期間 | 7年（電子帳簿保存法） | 同じ。期限前の削除は拒否する |

PDF生成のヘッドレスブラウザはVercel上で動かないため、**PDF生成専用の実行環境**に切り出す。
（Vercelの関数サイズ上限に収まらないため。ブラウザを含んだ実行環境を別に用意する）

## 9. 安全面

| 項目 | 内容 |
|---|---|
| 管理画面 | Googleログイン必須。許可したメールアドレスのみ |
| 2要素認証 | **Googleアカウント側の設定に委ねる**。自前でパスワードを持たないため、こちらでは必須化できない。オーナーのGoogleアカウントで2段階認証をオンにしていただく |
| 合いことば | AES-256-GCMで暗号化して保存。画面には末尾4文字のみ |
| LIFF | IDトークンをサーバーで検証。ユーザーIDを信用しない |
| Webhook | 署名を必ず確認 |
| 定時実行の受け口 | 合いことばで保護 |
| お客様の情報 | 他のお客様の予約は見られない（顧客IDで必ず絞る） |
| 通信 | すべてHTTPS |
| 記録 | 誰がいつ何をしたかを残す（予約・書類・つなぎ替え） |

## 10. お客さま（オーナー）にお願いすること

こちらでは代われない作業。**画面の中で1ステップずつご案内する**形にする。

### つなぐとき（最初の1回）

| # | やること | かかる時間 | 画面での案内 |
|---|---|---|---|
| 1 | LINE Developers に登録し、Messaging APIチャネルを作る | 10分 | あり |
| 2 | チャネルアクセストークンとチャネルシークレットを画面に貼る | 2分 | あり |
| 3 | Webhook URL をLINE側に貼る（画面からコピーできる） | 2分 | あり |
| 4 | LIFFアプリを作り、IDを画面に貼る | 5分 | あり |
| 5 | Google Cloud でカレンダーAPIを有効にし、OAuthクライアントを作る | 10分 | あり |

| 7 | 管理画面に入れるメールアドレスを決める | — | 環境変数 |

### 決めていただきたいこと

- 実際のメニュー名・料金・所要時間
- 営業時間、定休日
- インボイスの登録番号（取得済みであれば）
- 決算月、消費税の納め方（税理士さんとご相談のうえ）
- キャンセル料の決まり

いずれも**仮の値のままでも動く**ので、決まってから管理画面で書き換えれば足りる。

## 12. 環境変数（本番）

```
DATABASE_URL           本番DBへの接続（プール経由）
DIRECT_URL             同上（マイグレーション用の直結）
ENCRYPTION_KEY         合いことばを暗号化する鍵（32バイト）
AUTH_SECRET            ログインのセッションを守る鍵
AUTH_GOOGLE_ID         Googleログイン用
AUTH_GOOGLE_SECRET     同上
ADMIN_EMAILS           最初に管理画面へ入れるメールアドレス（カンマ区切り）
APP_BASE_URL           本番のURL
CRON_SECRET            定時実行の受け口を守る合いことば
BLOB_READ_WRITE_TOKEN  PDFの保管先
```

**LINE と Googleカレンダーの合いことばは、ここには書かない。** 画面から入れる。
乗り換えのたびに環境変数を書き換えて再デプロイする、という手間をなくすため。
